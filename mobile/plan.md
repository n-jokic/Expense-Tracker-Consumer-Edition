# Mobile App — Standalone Offline-First iOS/Android Companion

> Plan for a standalone phone app with full feature parity to the desktop Expense
> Tracker, adapted UI, autonomous operation, and **optional** sync to the PC
> instance over LAN / Tailscale / tunnel (seeded by the existing api.py v2
> protocol). Track progress with the checkboxes: [ ] todo / [~] in progress /
> [x] done (append date or commit).
>
> Baseline rule: pytest tests green before and after every phase. Desktop app
> **behavior/UI never changes**; desktop **code edits are additive-only** and
> start at Phase 2 (see Scope guard).

---

## Owner decisions (locked)

| Decision | Choice |
|---|---|
| Platform | React Native (Expo) + TypeScript domain core (runner-up: Flutter) |
| Repo organization | Monorepo — mobile/, protocol/, tools/golden_gen.py live here |
| Local storage | op-sqlite with SQLCipher (AES-256 parity with desktop); key in Keychain/Keystore |
| Conflict strategy | Whole-record conflict rows + manual resolution (matches Settings-Sync UX); field merge later; CRDTs rejected |
| AI strategy | Tiered: T0 deterministic routes, T1 on-device model, T2 delegate-to-PC, T3 BYOK cloud |
| Monetization | Free core + one-time Pro unlock (+ optional future relay). Never subscription-for-core, ads, or data sale |
| Bank aggregation | None, ever (manual/import only — positioning pillar) |
| Sync authority | PC remains authoritative whenever reachable; phone recomputes display values locally |

├── app.py  api.py  sync_core.py  db.py  services/  ai/  app_pages/

└── mobile/                            <- Expo app
    ├── plan.md                        <- THIS FILE

    ├── core/                          <- TS domain core: money math, validators
    │                                     - the golden-tested package

- CI: three jobs with path filters — Python suite / mobile TS tests /
  golden-parity job. Python churn always triggers parity checks; JS churn
  never blocks the finance suite.
- Versioning: mobile app version independent (store-driven); coupling only
  via negotiated schema_version.

## Edge cases & failure modes (design inputs)

Weeks-offline divergence (outbox + conflict cards); stale rates (dated
captions; server recomputes anyway); token expiry away from PC (long-lived
rotating tokens; re-pair at any reachability window); PC upgraded ahead of
phone (version gate -> clear prompt; local mode unaffected); concurrent edits
from two phones + PC (existing conflict-row flow); OCR misreads (review-sheet
gates unchanged); background-task kills (foreground sync + manual refresh);
phone loss (revocation + encryption-at-rest + no cloud copy).
